# MoonSSH 实现计划

> **架构：** MoonBit 实现 SSH 协议层，密码学全部走 OpenSSL FFI（`libcrypto`）

---

## 一、总体架构

```
cmd/main/main.mbt          CLI 入口
src/ssh_client.mbt         顶层 Client API（connect / kex / auth / shell / exec）
src/kex.mbt                KEX 状态机
src/auth.mbt               认证（password / publickey / keyboard-interactive）
src/channel.mbt            通道管理（open / shell / exec / pty / close）
src/packet.mbt             SSH 包编解码（Reader / Writer / 加解密帧化）
src/known_hosts.mbt        known_hosts 解析 & 交互式验证
───────────────────────────────────────────────
src/socket/socket.mbt+c    保留不动（TCP connect / read / write）
───────────────────────────────────────────────
src/crypto/openssl.c       AES-CTR / HMAC-SHA1/SHA256 / DH / ECDH / RSA / BN
src/crypto/cipher.mbt      FFI 绑定
src/crypto/mac.mbt         FFI 绑定
src/crypto/digest.mbt      SHA1 / SHA256 FFI 绑定
src/crypto/kex.mbt         DH Group14 / ECDH P-256 / X25519 FFI 绑定
src/crypto/pkey.mbt        RSA 签名/验证 FFI 绑定
src/crypto/error.mbt       密码学错误类型
```

---

## 二、模块分解

### 2.1 `src/crypto/` — 密码学 FFI 层

直接调用 OpenSSL `libcrypto`，每个原语一组 MoonBit 类型封装 + C FFI。

| 文件 | 暴露接口 | FFI 依赖 |
|---|---|---|
| `cipher.mbt` | `Cipher::aes128_ctr_encrypt/decrypt(key, iv, data)` | `EVP_EncryptInit_ex` / `EVP_DecryptInit_ex` (CTR mode) |
| `mac.mbt` | `Mac::hmac_sha1/sha256(key, data)` | `HMAC_CTX_new` / `HMAC_Init_ex` / `HMAC_Update` / `HMAC_Final` |
| `digest.mbt` | `Hash::sha1/sha256(data)` | `EVP_DigestInit_ex` / `EVP_DigestUpdate` / `EVP_DigestFinal_ex` |
| `kex.mbt` | `dh_generate(p, g)` `dh_shared(priv, peer, p)` `ecdh_generate(curve)` `ecdh_shared(key, peer_pub)` | `BN_new` / `BN_rand_range` / `BN_mod_exp` / `EVP_PKEY_keygen` / `EVP_PKEY_derive` |
| `pkey.mbt` | `rsa_sign(md, key, data)` `rsa_verify(md, key, data, sig)` `load_pem(path)` | `EVP_DigestSign` / `EVP_DigestVerify` / `PEM_read_PrivateKey` |

每个 `.mbt` 配一个 `openssl.c`（或共享一个大的 `openssl.c`），在 `moon.pkg` 中声明 `native-stub`。

### 2.2 `src/packet.mbt` — SSH 包编解码

**类型：**
```moonbit
// 读游标
struct Reader { data: Bytes, mut pos: Int }
  read_byte() -> Byte
  read_uint32() -> Int
  read_string() -> Bytes       // uint32 len + data
  read_string_as_str() -> String
  read_mpint() -> BigInt
  read_name_list() -> Array[String]
  read_bytes(n) -> Bytes

// 写缓冲
struct Writer { buf: Array[Byte] }
  write_byte(b)
  write_uint32(n)
  write_string(s)
  write_string_from_str(s)
  write_mpint(n)
  write_name_list(names)
  write_bytes(b)
  to_bytes() -> Bytes
```

**包帧化：**
```
read_packet(read_fn, block_size, mac_size, decrypt_fn, verify_mac_fn) -> Bytes
write_packet(payload, block_size, mac_enabled, compute_mac_fn) -> Bytes
```

实现 RFC 4253 §6 的二进制布局：
```
uint32  packet_length    (不含 MAC)
uint8   padding_length
byte[N] payload || padding
byte[M] MAC              (如果启用)
```

加密后：`encrypt(body) || MAC(seq || encrypt(body))`

### 2.3 `src/kex.mbt` — 密钥交换

**常量：**
```
SSH_MSG_KEXINIT = 20
SSH_MSG_NEWKEYS = 21
SSH_MSG_KEX_ECDH_INIT = 30
SSH_MSG_KEX_ECDH_REPLY = 31
```

**数据结构：**
```
struct KexInit {
  cookie: Bytes           // 16 bytes
  kex_algs: Array[String]
  host_key_algs: Array[String]
  enc_c2s: Array[String]
  enc_s2c: Array[String]
  mac_c2s: Array[String]
  mac_s2c: Array[String]
  comp_c2s: Array[String]
  comp_s2c: Array[String]
}

struct EcdhReply {
  host_key: Bytes
  server_public: Bytes
  signature: Bytes
}

struct DhReply {
  host_key: Bytes
  f: BigInt
  signature: Bytes
}

struct DerivedKeys {
  iv_c2s, iv_s2c: Bytes           // 各 16
  enc_key_c2s, enc_key_s2c: Bytes // 各 16 (AES-128)
  mac_key_c2s, mac_key_s2c: Bytes // 各 20/32 (SHA1/SHA256)
}

enum KexState { Initial, SentKexinit, Negotiating, SentDhInit, ComputingHash, ReadyForNewKeys, InstallKeys, Done }
```

**核心流程：** `drive(read_fn, write_fn, host_key_verifier)`

```
1. 构造并发送 SSH_MSG_KEXINIT
   - kex_algorithms:   ["ecdh-sha2-nistp256", "diffie-hellman-group14-sha256", "diffie-hellman-group14-sha1"]
   - host_key:         ["rsa-sha2-256", "ssh-rsa"]
   - encryption:       ["aes128-ctr"]
   - mac:              ["hmac-sha2-256", "hmac-sha1"]
   - compression:      ["none"]

2. 接收服务器 KEXINIT → 协商算法（first match wins）

3. 根据协商的 KEX 算法发起点对点交换：
   【ECDH P-256 分支】
     a. ecdh_generate() → (priv, Q_C)
     b. 构造 ECDH_INIT(Q_C) 并发送
     c. 接收 ECDH_REPLY → (K_S, Q_S, signature)
     d. ecdh_shared(priv, Q_S) → K
     e. H = sha256(V_C || V_S || I_C || I_S || K_S || Q_C || Q_S || K)
     f. rsa_verify(host_key, H, signature) → 验证

   【DH Group14 分支】
     a. rand(256 bytes) → x，保证奇数
     b. e = g^x mod p
     c. 构造 DH_INIT(e) 并发送
     d. 接收 DH_REPLY → (K_S, f, signature)
     e. K = f^x mod p
     f. H = sha256/sha1(V_C || V_S || I_C || I_S || K_S || e || f || K)
     g. rsa_verify(host_key, H, signature) → 验证

4. H 作为 session_id（首次 KEX）

5. 密钥派生（RFC 4253 §7.2）：
   iv_c2s  = KDF(K, H, 'A', session_id)   // key = hash(K||H||X||session_id)
   iv_s2c  = KDF(K, H, 'B', session_id)
   ek_c2s  = KDF(K, H, 'C', session_id)
   ek_s2c  = KDF(K, H, 'D', session_id)
   mk_c2s  = KDF(K, H, 'E', session_id)
   mk_s2c  = KDF(K, H, 'F', session_id)

6. 发送 NEWKEYS，接收 NEWKEYS
7. 激活加密
```

**算法协商函数：**
```
pick_first(our: Array[String], server: Array[String]) -> String?
```

### 2.4 `src/auth.mbt` — 用户认证

**Message types：**
```
SSH_MSG_SERVICE_REQUEST = 5
SSH_MSG_SERVICE_ACCEPT = 6
SSH_MSG_USERAUTH_REQUEST = 50
SSH_MSG_USERAUTH_FAILURE = 51
SSH_MSG_USERAUTH_SUCCESS = 52
SSH_MSG_USERAUTH_INFO_REQUEST = 60
SSH_MSG_USERAUTH_INFO_RESPONSE = 61
```

**数据结构：**
```
enum AuthReply {
  Success
  Failure(methods: Array[String], partial: Bool)
  InfoRequest(name, instruction, prompts: Array[Prompt])
}

struct Prompt { prompt: String, echo: Bool }

enum AuthMethod { Password(String), PublicKey(String), KeyboardInteractive, None }
```

**API：**
```
// 消息构建
build_service_request(service) -> Bytes
build_userauth_request(user, service, method, ...) -> Bytes
build_userauth_info_response(responses) -> Bytes

// 消息解析
parse_auth_reply(payload) -> AuthReply
parse_userauth_info_request(payload) -> InfoRequest

// 签名输入（RFC 4252 §7）
build_publickey_signature_input(session_id, user, alg, blob) -> Bytes
```

**三种认证方法：**

1. **Password：**
   ```
   build_userauth_request(user, "ssh-connection", "password", password, change=false)
   ```

2. **PublicKey（two-step）：**
   ```
   Step 1 — Query:
     build_userauth_request(user, "ssh-connection", "publickey", has_signature=false, alg, blob)
   Step 2 — Sign（收到 PublicKeyOk 后）:
     input = build_publickey_signature_input(session_id, user, alg, blob)
     sig = rsa_sign(sha256, private_key, input)
     build_userauth_request(user, "ssh-connection", "publickey", has_signature=true, alg, blob, sig)
   ```

3. **Keyboard-Interactive：**
   ```
   Step 1:
     build_userauth_request(user, "ssh-connection", "keyboard-interactive", lang="", submethods="")
   Step 2-N（收到 InfoRequest 后）:
     prompt 用户逐项输入
     build_userauth_info_response(responses)
   ```

### 2.6 `src/known_hosts.mbt` — 主机密钥验证

**功能：**
```
// 解析
parse_line(line: String) -> KnownHost?
parse_file(path: String) -> Array[KnownHost]
parse_file_content(content: String) -> Array[KnownHost]

// 匹配
KnownHost::matches(host: String, port: Int) -> Bool
KnownHost::key_bytes() -> Bytes

// 验证流程
verify_host_key(host, port, key_alg, key_bytes, known_hosts_path) -> Bool
  → 若已信任：返回 true
  → 若密钥变化：警告用户
  → 若新主机：显示 fingerprint，询问用户
  → 用户确认后追加到 known_hosts 文件

// Fingerprint
sha256_fingerprint(key_bytes) -> String  // "SHA256:xxxx..."
```

### 2.7 `src/ssh_client.mbt` — 客户端 API

**核心类型：**
```
struct Client {
  conn: Tcp                    // socket
  banner_client: String
  banner_server: String
  kex_state: KexState
  session_id: Bytes
  encrypted: Bool
  cipher_c2s: Cipher, cipher_s2c: Cipher
  mac_c2s: Mac, mac_s2c: Mac
  seq_send: Int, seq_recv: Int
}

struct ConnectOptions {
  host: String, port: Int
  user: String
  client_banner: String?           // 默认 "SSH-2.0-MoonSSH_0.1.0"
  accept_host_key: (String, Bytes) -> Bool
}
```

**API：**
```
// 连接
Client::connect(opts: ConnectOptions) -> Client

// 密钥交换
Client::kex(self) -> Unit

// 认证（单一方法）
Client::auth_password(self, password: String) -> Unit
Client::auth_publickey(self, key_path: String) -> Unit
Client::auth_keyboard_interactive(self, answer_fn: (Prompt) -> String) -> Unit

// 认证（自动回退）
Client::auth_auto(self, opts: AuthOptions) -> Unit
  // 发送 "none" 探测 → 获取方法列表 → 按序尝试
  // 优先级：publickey → keyboard-interactive → password

// 通道操作
Client::open_session(self) -> Channel
Client::exec(self, channel: Channel, command: String) -> String
Client::shell(self, channel: Channel, with_pty: Bool) -> Unit

// 关闭
Client::close(self) -> Unit
```

**内部方法（加解密包 I/O）：**
```
read_plain_packet(self) -> Bytes
write_plain_packet(self, payload) -> Unit
read_encrypted_packet(self) -> Bytes
write_encrypted_packet(self, payload) -> Unit
install_encryption(self, keys: DerivedKeys) -> Unit
```

### 2.9 `cmd/main/main.mbt` — CLI

参考 `gbonacini_tssh/src/Main.cpp`。

**参数：**
```
moonssh [user@]host [-p port] [-l user] [-i identity] [-T] [-d] [-V]
  user@host      目标主机（必须）
  -p <port>      端口（默认 22）
  -l <user>      用户名（可与 host 分开指定）
  -i <identity>  密钥文件前缀（默认 "id_rsa"）
  -T             不分配 PTY（仅执行命令模式）
  -d             调试模式（hex dump 所有包）
  -V             版本信息
```

**主流程：**
```
1. 解析参数
2. Tcp::connect_to_host(host, port)       // socket 层
3. 发送 "SSH-2.0-MoonSSH_0.1.0\r\n"      // banner
4. 读取服务器 banner
5. KEX (kex.drive)                        // 密钥交换
6. auth_auto (pubkey → kbd-int → password) // 认证（自动回退）
7. open_session → shell (交互) 或 exec    // 通道
8. close
```

## 三、实施步骤

### Step 1 — 密码学 FFI 层（`src/crypto/`）

| 任务 | 产出 |
|---|---|
| 创建 `openssl.c` | AES-CTR、HMAC-SHA1/256、SHA1/256、DH modp2048、ECDH P-256、BN 运算、RSA sign/verify、PEM 加载 |
| `cipher.mbt` | `Cipher` 类型封装 |
| `mac.mbt` | `Mac` 类型封装 |
| `digest.mbt` | `Hasher` 类型封装 |
| `kex.mbt` | `dh_generate` / `dh_shared` / `ecdh_generate` / `ecdh_shared` |
| `pkey.mbt` | `load_pem` / `rsa_sign` / `rsa_verify` |
| `error.mbt` | `CryptoError` 类型 |

### Step 2 — 包编解码（`src/packet.mbt`）

Reader / Writer / read_packet / write_packet。

### Step 3 — KEX（`src/kex.mbt`）

KEXINIT 协商 → ECDH P-256 → DH Group14 → exchange hash → 密钥派生 → NEWKEYS。

### Step 4 — 认证（`src/auth.mbt`）

password / publickey / keyboard-interactive / auto 回退。

### Step 5 — 通道（`src/channel.mbt`）

通道管理：open / exec / close，以及 shell 消息构建（不含终端 raw mode）。

### Step 6 — 已知主机（`src/known_hosts.mbt`）

解析、匹配、验证、fingerprint。

### Step 7 — 客户端 API + CLI（`src/ssh_client.mbt` + `cmd/main/`）

组装所有模块，提供完整 CLI。

## 四、OpenSSL FFI 接口清单

所有密码学操作走 `src/crypto/openssl.c`。

| 类别 | FFI 函数 | OpenSSL API |
|---|---|---|
| **AES-CTR** | `aes_ctr_encrypt(key, iv, data) -> bytes` | `EVP_EncryptInit_ex(EVP_aes_128_ctr())` + `EVP_EncryptUpdate` |
| | `aes_ctr_decrypt(key, iv, data) -> bytes` | `EVP_DecryptInit_ex(EVP_aes_128_ctr())` + `EVP_DecryptUpdate` |
| **HMAC** | `hmac_sha1(key, data) -> digest` | `HMAC_CTX_new` → `HMAC_Init_ex(EVP_sha1())` → `HMAC_Update` → `HMAC_Final` |
| | `hmac_sha256(key, data) -> digest` | 同上，`EVP_sha256()` |
| **Hash** | `sha1(data) -> digest` | `EVP_DigestInit_ex(EVP_sha1())` → `EVP_DigestUpdate` → `EVP_DigestFinal_ex` |
| | `sha256(data) -> digest` | 同上，`EVP_sha256()` |
| **DH** | `dh_gen_key(p, g) -> (priv, pub)` | `BN_new` / `BN_rand_range` / `BN_mod_exp` |
| | `dh_compute_key(priv, peer, p) -> shared` | `BN_mod_exp` |
| **ECDH P-256** | `ecdh_gen_key() -> (priv, pub)` | `EVP_PKEY_keygen(NID_X9_62_prime256v1)` |
| | `ecdh_derive(priv, peer_pub) -> shared` | `EVP_PKEY_derive` |
| **RSA** | `rsa_sign(md, key, data) -> sig` | `EVP_DigestSign` |
| | `rsa_verify(md, key, data, sig) -> bool` | `EVP_DigestVerify` |
| | `pem_read_private_key(path) -> key` | `PEM_read_PrivateKey` / `PEM_read_bio_PrivateKey` |
| **BigNum** | `bn_from_bytes(bytes) -> bn` | `BN_bin2bn` |
| | `bn_to_bytes(bn, size) -> bytes` | `BN_bn2binpad` / `BN_bn2bin` |
| | `bn_to_mpint(bn) -> bytes` | `BN_bn2bin` + SSH mpint 补 0x00 头 |
| **随机数** | `crypto_rand_bytes(n) -> bytes` | `RAND_bytes` |

## 五、支持的算法

| 类别 | 算法 |
|---|---|
| KEX | `ecdh-sha2-nistp256`、`diffie-hellman-group14-sha256`、`diffie-hellman-group14-sha1` |
| 主机密钥 | `rsa-sha2-256`、`ssh-rsa` |
| 对称加密 | `aes128-ctr` |
| MAC | `hmac-sha2-256`、`hmac-sha1` |
| 压缩 | `none` |
