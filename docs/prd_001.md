# PRD-001：MoonSSH 实现规约（AI Agent 执行版）

> 本文档是 [prd_000.md](prd_000.md) 分析结论的执行落地版。AI agent 应当按本文档的步骤顺序执行，每完成一步做对应验证，遇到"停止询问"条件时立即中断并询问用户。

## 1. 目标

交付一个**协议层完全 MoonBit 原创**的 SSHv2 客户端库，通过 FFI 调用系统 OpenSSL `libcrypto` 实现密码学原语。

## 2. 关键决策（已与用户确认，无需再询问）

| 决策点 | 结论 | 依据 |
|--------|------|------|
| TCP 传输 | 用 `moonbitlang/async/socket`，**不**自写 socket FFI | 官方包，质量高，减少 230 行 C 代码 |
| TLS 协议 | 不用，SSH 自带安全层 | TLS 与 SSH Transport Layer 平行，不能叠加 |
| 密码学实现 | FFI 调系统 OpenSSL `libcrypto` | 与 `russh` / `golang.org/x/crypto/ssh` 同模式 |
| FFI 工程范式 | 复制 `moonbitlang/async/tls` 的 `openssl_loader.mbt` + `crypto_util.mbt` | Apache 2.0 兼容，省 1-2 周工程量 |
| libssh2 绑定 | 删除 | 违反"协议层原创"目标，与 `moon.mod` 中 license 定位冲突 |
| 派生代码声明 | 必须在 `src/ffi/crypto/NOTICE` 完整列出 | Apache 2.0 第 4 条要求 |

## 3. 约束（agent 必须遵守）

### 3.1 不可做
- ❌ 不得保留任何 libssh2 FFI 调用（[src/ffi/libssh2.mbt](../src/ffi/libssh2.mbt) 与 [src/ffi/socket.mbt](../src/ffi/socket.mbt) 必须删除）
- ❌ 不得在 MoonBit 中手写任何密码学原语（SHA-2、HMAC、AES、Curve25519、Ed25519、RSA、BN）
- ❌ 不得在 FFI 中使用 OpenSSL 3.x 独占 API（仅用 1.1+ 通用 API）
- ❌ 不得使用 `#internal` 标记的 `moonbitlang/async/tls` 内部函数（应复制到自有模块后去掉该标记）
- ❌ 不得修改从 `async/tls` 复制的源文件的版权头

### 3.2 必须做
- ✅ 每完成一个文件立即 `moon fmt && moon info && moon test` 验证
- ✅ 派生自 `async/tls` 的文件必须在文件头保留原 Apache 2.0 版权声明
- ✅ 在 `src/crypto/NOTICE` 列出所有派生文件 + 完整 Apache 2.0 LICENSE 文本
- ✅ 集成测试用 `docker.io/linuxserver/openssh-server` 起真实 sshd
- ✅ 每个 PR 提交前跑 `moon coverage analyze`，目标覆盖 ≥ 70%

## 4. 目标架构

> 所有源文件统一放在 `src/` 目录下，与 [moon.mod](../moon.mod) 平级。

**操作**：

   - `openssl_loader.mbt` → `src/crypto/openssl_loader.mbt`

3. **修改** `rand.mbt`：
   - 删除 `#internal` 标记
   - 命名空间从 `moonbitlang/async/tls` 改为 `crypto`

**验证**：

### Step 3：编写 FFI/crypto 新模块

**目标**：覆盖 SSH 所需的所有密码学原语。

**模块清单与行数预估**：

| 文件 | 内容 | 行数 |
|------|------|------|
| `digest.mbt` | SHA-1 / SHA-256 / SHA-512 via `EVP_Digest*` | 80 |
| `mac.mbt` | HMAC via `EVP_MAC_*` | 60 |
| `cipher.mbt` | AES-128/256-CTR、AES-128/256-GCM、ChaCha20-Poly1305 via `EVP_CIPHER_*` | 150 |
| `pkey.mbt` | `EVP_PKEY_*` 包装：Ed25519 sign/verify、RSA sign/verify、ECDSA sign/verify | 200 |
| `kex.mbt` | X25519 via `EVP_PKEY_derive`、nistp256 ECDH、DH group14 via `BN_*` | 180 |
| `bignum.mbt` | `BN_new` / `BN_bin2bn` / `BN_bn2bin` / `BN_mod_exp` / `BN_free` | 80 |
| `error.mbt` | 统一 `CryptoError` suberror + 字符串映射 | 40 |

**实现顺序**（先易后难，每步独立验证）：
1. `error.mbt`（无依赖）
2. `digest.mbt`（依赖 `error.mbt`、`loader.c`）
3. `bignum.mbt`（依赖 `error.mbt`）
4. `mac.mbt`（依赖 `digest.mbt`）
5. `cipher.mbt`（依赖 `error.mbt`）
6. `kex.mbt`（依赖 `bignum.mbt`、`pkey.mbt`）
7. `pkey.mbt`（依赖 `digest.mbt`、`error.mbt`）

**每个文件完成后**：
```bash
moon fmt && moon info && moon build
```

**停止条件**：
- 任何 `moon build` 失败，先尝试解决；连续 3 次失败停止询问用户
- 任何 OpenSSL 符号在目标系统（Windows MinGW、Linux glibc、macOS）缺失，立即停止询问用户


### Step 4：实现 SSH 协议层

**目标**：从 RFC 4253 出发，在 MoonBit 中重写 SSH 状态机。

**实现顺序**：

1. `src/packet.mbt`（依赖 `src/crypto/cipher`, `src/crypto/mac`）
   - 二进制包读写
   - length / padding_length / payload / padding / MAC
   - 加密 / 解密（CTR 模式 + HMAC；AEAD 模式自包含）

2. `src/kex.mbt`（依赖 `src/packet.mbt`, `src/crypto/kex`, `src/crypto/digest`, `src/crypto/pkey`）
   - 状态机：INIT → KEXINIT → KEXDH_INIT / KEXECDH_INIT → KEXDH_REPLY → NEWKEYS
   - 实现 `curve25519-sha256` 与 `ecdh-sha2-nistp256` 两条线
   - 派生密钥（HKDF-SHA2-256 / SHA-512 via `EVP_KDF`）

3. `src/auth.mbt`（依赖 `src/packet.mbt`）
   - `ssh-userauth` 服务请求
   - 密码认证方法
   - 公钥认证方法（query → sign → verify）

4. `src/known_hosts.mbt`（无核心依赖）
   - 解析 `~/.ssh/known_hosts`
   - 写入新条目
   - 主机指纹比对

5. `src/channel.mbt`（依赖 `src/packet.mbt`, `src/auth.mbt`）
   - `session` 通道打开
   - `exec` 请求 / 响应
   - `shell` 请求
   - 窗口调整与数据转发
   - `exit-status` 解析

6. `src/sftp.mbt`（v0.2 stub）
   - 仅定义 `Sftp` 类型与方法签名
   - 实现推迟到 v0.2

7. `ssh_client.mbt`（依赖以上所有）
   - 顶层 API：`Client::connect`、`auth_password`、`auth_publickey`、`exec`、`close`
   - 与 [docs/项目申报书.md](项目申报书.md) §"拟实现的核心功能" 对齐

8. `cmd/main/main.mbt`
   - CLI 演示：解析参数 → connect → auth → exec → 输出结果

**每完成一个文件**：
```bash
moon fmt && moon info && moon build
```

agent 在以下情况**必须**停止当前任务、报告状态、等待用户回复：

1. 任何 `moon build` 连续 3 次失败
2. OpenSSL 在目标平台缺失关键符号
3. 集成测试在 `openssh-server` 容器上失败，且错误信息指向协议层（不是测试容器配置）
4. 时间已到第 4 周（5 月 19 日对应），但 KEX 状态机未跑通
5. 派生代码的版权头被误删
6. 发现需要用户做决策的歧义（例如：是否支持 agent 转发、是否实现 SFTP v0.1）
